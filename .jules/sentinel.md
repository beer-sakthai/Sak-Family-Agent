## 2026-11-20 - [Sentinel] SSRF Protection Bypass via Whitespace and Control Characters
**Vulnerability:** The Microsoft Graph API client (`services/teams-copilot-mcp/src/teams_copilot_mcp/graph_client.py`) implemented SSRF and protocol-relative URL protections (e.g., blocking `//attacker.com`) using `path.startswith(...)`. However, an attacker could bypass this check by prepending whitespace (e.g., `" //attacker.com"`) or ASCII control characters (e.g., `"\rhttps://attacker.com"`) to the path. Since the underlying HTTP libraries (`httpx` or `urllib.request`) typically strip or ignore leading whitespace and specific control characters during request building, the malicious payload would still be executed against the attacker's server, circumventing the intended restriction to `graph.microsoft.com`.
**Learning:** Security checks that rely on exact prefix matching (like `.startswith()`) are inherently brittle when dealing with network inputs that will subsequently be parsed or normalized by lower-level libraries. The divergence between the security validation logic (strict string matching) and the operational logic (tolerant parsing) creates a parsing differential vulnerability.
**Prevention:** Always normalize (e.g., `.strip()`) and sanitize (e.g., reject ASCII control characters) input *before* performing security validation. Validation logic must operate on the exact same representation of the data that will be consumed by the execution sink.
## 2026-11-20 - [Sentinel] SSRF Protection Bypass via Whitespace and Control Characters in TS
**Vulnerability:** The SakThai API client (`apps/sak_agent_dashboard/src/lib/sources/api.ts`) implemented SSRF and path traversal protections (e.g., blocking `//attacker.com` and `https://attacker.com`) using `validationPath.includes("\\")` and comparing `origin`. However, an attacker could bypass this check by prepending whitespace (e.g., `" //attacker.com"`) or ASCII control characters (e.g., `"\rhttps://attacker.com"`) to the path. Since the underlying HTTP libraries (`fetch`) typically strip or ignore leading whitespace and specific control characters during request building, the malicious payload would still be executed against the attacker's server, circumventing the intended restriction to the base URL and leaking the API token.
**Learning:** Security checks that rely on exact matching or prefix matching are inherently brittle when dealing with network inputs that will subsequently be parsed or normalized by lower-level libraries (like `fetch` in JS). The divergence between the security validation logic (strict string matching) and the operational logic (tolerant parsing) creates a parsing differential vulnerability.
**Prevention:** Always normalize (e.g., `.trim()`) and sanitize (e.g., reject ASCII control characters) input *before* performing security validation. Validation logic must operate on the exact same representation of the data that will be consumed by the execution sink.
## 2024-10-22 - Replace xml.etree.ElementTree with defusedxml to prevent XML attacks
**Vulnerability:** The standard library `xml.etree.ElementTree` is vulnerable to XML attacks such as Billion Laughs and XXE (flagged by Bandit B405/B314).
**Learning:** `xml.etree.ElementTree` was used extensively in skills for parsing arXiv results and modifying Office Open XML documents (PowerPoint redlines).
**Prevention:** Always use `defusedxml.ElementTree` (or `defusedxml.minidom`) when parsing untrusted XML, as it is a drop-in replacement that safely defuses malicious entities. Ensure updates are applied symmetrically across duplicated persona skill files.
## 2024-10-23 - Avoid restricted eval anti-pattern
**Vulnerability:** Command Injection via `eval()`. Attempting to secure `eval()` by restricting globals/locals (e.g., `eval(expr, {"__builtins__": {}})`) is an anti-pattern and does NOT prevent sandbox escapes.
**Learning:** Python's object introspection allows traversing `().__class__.__bases__[0].__subclasses__()` to bypass the restricted dictionary and execute arbitrary commands.
**Prevention:** Never use `eval()` on user input. Use secure evaluators like `ast.literal_eval` for literals, or dedicated safe-parsing libraries like `simpleeval` for mathematical expressions.
