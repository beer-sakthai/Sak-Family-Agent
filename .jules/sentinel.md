## 2026-07-24 - Case-Insensitivity Bypass in Defense-In-Depth File-Read Blocker
**Vulnerability:** Case-sensitivity bypass in `_is_sensitive_read_target` inside the `read_file` tool handler (`tools.py`). While the outer `guardrails.py` used case-insensitive `.casefold()` matching for sensitive paths, the inner `tools.py` checked requested files and path parts with case-sensitivity (e.g. `name in _SENSITIVE_READ_BASENAMES`). On case-insensitive filesystems like macOS or Windows, a client could bypass this block to read sensitive files (such as `.ENV`, `CREDENTIALS.JSON`, or `.SSH/id_rsa`).
**Learning:** Security gates placed at different layers of an application (e.g., outer guardrails vs. inner tool-resolver defense-in-depth) can drift or differ in validation semantics, leading to unexpected bypasses of the inner boundary.
**Prevention:** Always ensure that file validation, denylists, and path checks are fully normalized and case-insensitive (converting inputs to lowercase or using casefold) across all defensive boundaries, especially when running on or supporting case-insensitive host filesystems.
