## 2026-11-20 - [Sentinel] SSRF Protection Bypass via Whitespace and Control Characters
**Vulnerability:** The Microsoft Graph API client (`services/teams-copilot-mcp/src/teams_copilot_mcp/graph_client.py`) implemented SSRF and protocol-relative URL protections (e.g., blocking `//attacker.com`) using `path.startswith(...)`. However, an attacker could bypass this check by prepending whitespace (e.g., `" //attacker.com"`) or ASCII control characters (e.g., `"\rhttps://attacker.com"`) to the path. Since the underlying HTTP libraries (`httpx` or `urllib.request`) typically strip or ignore leading whitespace and specific control characters during request building, the malicious payload would still be executed against the attacker's server, circumventing the intended restriction to `graph.microsoft.com`.
**Learning:** Security checks that rely on exact prefix matching (like `.startswith()`) are inherently brittle when dealing with network inputs that will subsequently be parsed or normalized by lower-level libraries. The divergence between the security validation logic (strict string matching) and the operational logic (tolerant parsing) creates a parsing differential vulnerability.
**Prevention:** Always normalize (e.g., `.strip()`) and sanitize (e.g., reject ASCII control characters) input *before* performing security validation. Validation logic must operate on the exact same representation of the data that will be consumed by the execution sink.

## 2026-11-20 - [Sentinel] Command Injection / Arbitrary Code Execution in Markdown Files via eval()
**Vulnerability:** The documentation file `personas/sakking/skills/SakKing-smolagents/SKILL.md` provided a code snippet using `eval(expression)` for a calculator tool. Code snippets and examples in documentation, markdown files, and SKILL instructions that are passed to AI agents act as direct instructions. An agent reading this documentation would adopt and execute `eval(expression)` for arbitrary math evaluation, leading to a Command Injection / Arbitrary Code Execution vulnerability if an attacker supplied a malicious string like `__import__('os').system('malicious_command')`.
**Learning:** Code snippets in documentation and SKILL files are not just passive text; they become executable active code when consumed and replicated by AI agents. Providing insecure code examples in documentation directly introduces vulnerabilities into the running application via the agents. Restricting `__builtins__` in `eval()` is a known anti-pattern and does NOT prevent sandbox escapes.
**Prevention:** Always secure code snippets in documentation and instructions just as rigorously as the main application code. Replace unsafe functions like `eval()` with secure alternatives (e.g., `simpleeval.simple_eval()` or `ast.literal_eval()` where appropriate). When introducing third-party alternatives like `simpleeval` in markdown snippets, explicitly document the dependency (e.g., `# Requires: pip install simpleeval`) to prevent user friction.
