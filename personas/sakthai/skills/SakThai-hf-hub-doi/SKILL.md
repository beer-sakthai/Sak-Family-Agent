# HF Hub DOI Deep Dive — DataCite Integration & Metadata Schema

## Overview

The Hugging Face Hub offers DOI (Digital Object Identifier) generation for
models and datasets through a partnership with **DataCite**. DOIs are persistent
identifiers tied to a digital object's metadata (URL, version, creation date,
description, creators). They serve as a stable, citable reference for ML
artifacts in academic publishing — analogous to an ISBN for books.

When you generate a DOI for a Hub repository, HF sends kernel-4 XML metadata to
DataCite, making your model/dataset discoverable via DataCite's search and
citation services.

## Core Facts

| Feature | Detail |
|---------|--------|
| DOI Prefix | `10.57967/hf/` + numeric ID (e.g. `10.57967/hf/8345`) |
| Registration Agency | DataCite (https://datacite.org) |
| Publisher in Metadata | `Hugging Face` |
| Resource Types | `Dataset` (for datasets), `Model` (for models) |
| Version | Set to the git commit SHA at time of DOI generation |
| URL | Links to the HF repo page |
| Content URL | Links to the specific revision tree on HF |
| Locking Scope | Deletion, rename, visibility change blocked |
| Cost | Free (no charge for DOI generation on HF Hub) |
| Scope | Models and datasets only (not Spaces) |
| Programmatic Generation | Not available via API — requires UI consent flow |
| API Querying | DataCite REST API fully queryable for metadata |

## DataCite Metadata Schema (Kernel 4.x)

HF sends DataCite kernel-4 XML metadata when registering a DOI. The schema
includes these elements (based on DataCite Kernel 4.5):

### Required Elements

```xml
<resource xmlns="http://datacite.org/schema/kernel-4"
          xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
          xsi:schemaLocation="http://datacite.org/schema/kernel-4
          http://schema.datacite.org/meta/kernel-4/metadata.xsd">
  <identifier identifierType="DOI">10.57967/HF/8345</identifier>
  <creators>
    <creator>
      <creatorName nameType="Personal">Author Name</creatorName>
    </creator>
  </creators>
  <titles>
    <title>Repository Name</title>
  </titles>
  <publisher>Hugging Face</publisher>
  <publicationYear>2026</publicationYear>
  <resourceType resourceTypeGeneral="Dataset"/>
  <version>commit-sha</version>
</resource>
```

### Element Mapping: HF Repo → DataCite

| DataCite Field | HF Source | Notes |
|---------------|-----------|-------|
| `identifier` | Generated by DataCite | Format: `10.57967/HF/{ID}` — case-insensitive, HF uses uppercase `HF` |
| `creators[].creatorName` | User's public profile name (customizable) | Optional: user can personalize author list before generation. `nameType="Personal"` always. |
| `creators[].affiliation` | Not sent by HF | Empty array in current implementation |
| `titles[].title` | Repo name | The exact repo name (e.g. "ICNDelay", not the full path) |
| `publisher` | Always `Hugging Face` | Hard-coded string |
| `publicationYear` | Year of DOI generation | 4-digit year |
| `resourceType.resourceTypeGeneral` | `Dataset` or `Model` | Determined by repo type. HF maps "Dataset" for datasets. For models, potentially "Software" or "Model" (check actual DataCite controlled list) |
| `version` | Git commit SHA | Full SHA at time of generation (e.g. `a351b83` — abbreviated SHA) |
| `url` | HF repo URL | e.g. `https://huggingface.co/datasets/petchthwr/ICNDelay` |
| `contentUrl` | Revision tree URL | e.g. `https://huggingface.co/datasets/petchthwr/ICNDelay/tree/a351b83...` |

### Elements NOT Sent by HF

The following DataCite elements are **not included** in current HF DOI registrations:
- `descriptions` / `descriptionType` — no abstract or description provided
- `subjects` — no keywords
- `contributors` — only creators listed
- `dates` — no issuance/creation dates (only `publicationYear`)
- `language`
- `rightsList` — no license information
- `relatedIdentifiers` — no links to papers, source code, etc.
- `geoLocations`
- `fundingReferences`
- `sizes`
- `formats`

This means HF DOIs carry minimal metadata compared to Zenodo or DataCite DOIs
from other sources. The repo name, authors, and version are the primary metadata.

## DataCite REST API — Querying HF DOIs

HF DOIs are fully queryable through the DataCite REST API. This is the **only
programmatic way** to check if a repo has a DOI and to retrieve its metadata.

### Base API
```
https://api.datacite.org/dois
```

### Search by Prefix (all HF DOIs)
```http
GET https://api.datacite.org/dois?query=10.57967/hf&page[size]=20&sort=-created
```

### Get Single DOI
```http
GET https://api.datacite.org/dois/10.57967%2Fhf%2F8345
```

The DOI in the URL must have `/` percent-encoded as `%2F`.

### Response Format

The response is JSON:API compliant. The `data` object contains:

| Field | Description |
|-------|-------------|
| `id` | DOI string (e.g. `10.57967/hf/8345`) |
| `type` | Always `"dois"` |
| `attributes.doi` | The DOI |
| `attributes.prefix` | `10.57967` |
| `attributes.suffix` | `hf/8345` |
| `attributes.creators` | Array of `{name, nameType, affiliation[], nameIdentifiers[]}` |
| `attributes.titles` | Array of `{title}` |
| `attributes.publisher` | `"Hugging Face"` |
| `attributes.publicationYear` | 4-digit year |
| `attributes.types` | `{resourceTypeGeneral, schemaOrg, citeproc, bibtex, ris}` |
| `attributes.version` | Git commit SHA |
| `attributes.url` | HF repo URL |
| `attributes.contentUrl` | Array of revision tree URLs |
| `attributes.state` | `"findable"` (active) or `"registered"` |
| `attributes.xml` | Base64-encoded kernel-4 XML metadata |
| `attributes.created` | ISO datetime of registration |
| `attributes.updated` | ISO datetime of last update |
| `attributes.viewCount` | View count (DataCite side, not HF) |
| `attributes.citationCount` | Citation count |

### Python Example: Check if a Repo Has a DOI

```python
import requests

def check_hf_repo_doi(repo_id: str, repo_type: str = "model") -> dict | None:
    """Check if an HF repo has a DOI by querying DataCite API.

    Returns DOI metadata dict or None if not found.

    Limitations: Relies on title match against repo name.
    HF doesn't expose DOIs in its own API, so this is the
    only programmatic way to detect DOIs.
    """
    dc_api = "https://api.datacite.org/dois"
    params = {
        "query": f"10.57967/hf {repo_id.split('/')[-1]}",
        "page[size]": 5
    }
    resp = requests.get(dc_api, params=params)
    resp.raise_for_status()
    data = resp.json().get("data", [])

    for item in data:
        attrs = item["attributes"]
        if attrs.get("url") and repo_id in attrs["url"]:
            return attrs
    return None

# Example
metadata = check_hf_repo_doi("petchthwr/ICNDelay", "dataset")
if metadata:
    print(f"DOI: {metadata['doi']}")
    print(f"Version: {metadata['version']}")
    print(f"Citation: {metadata['doi']}")
```

### Python Example: Get Full Metadata (Including XML)

```python
import requests, base64, xml.etree.ElementTree as ET

def get_doi_metadata(doi: str) -> dict:
    """Fetch full DataCite metadata for an HF DOI."""
    encoded_doi = doi.replace("/", "%2F")
    url = f"https://api.datacite.org/dois/{encoded_doi}"
    resp = requests.get(url)
    resp.raise_for_status()
    return resp.json()["data"]["attributes"]

def decode_doi_xml(attributes: dict) -> str:
    """Decode the base64-encoded XML metadata."""
    xml_b64 = attributes.get("xml", "")
    if not xml_b64:
        return ""
    return base64.b64decode(xml_b64).decode("utf-8")

# Usage
attrs = get_doi_metadata("10.57967/hf/8345")
xml_str = decode_doi_xml(attrs)
print(xml_str)
```

### Citation Formats

The DataCite API returns citation-ready format info under `attributes.types`:

| Format | Example |
|--------|---------|
| **BibTeX** | `@misc{...}` for datasets |
| **RIS** | `TYPE: DATA` for datasets |
| **CSL** (citeproc) | `"article"` or `"dataset"` |
| **schemaOrg** | `"Dataset"` or `"SoftwareSourceCode"` |

You can generate citations using the DataCite Content Negotiation:
```http
GET https://api.datacite.org/dois/10.57967%2Fhf%2F8345
Accept: application/x-bibtex
```

Supported content types:
- `application/vnd.citationstyles.csl+json` — CSL-JSON
- `application/x-bibtex` — BibTeX
- `application/x-research-info-systems` — RIS
- `application/vnd.datacite.datacite+xml` — DataCite XML

## DOI Lifecycle

```mermaid
flowchart LR
    A[Create model/dataset] --> B[Settings → DOI section]
    B --> C[Click 'Generate DOI']
    C --> D[Accept DataCite terms]
    D --> E[Customize authors (optional)]
    E --> F[DataCite registers DOI ✓]
    F --> G[DOI badge appears in repo header]
    G --> H[New revision pushed]
    H --> I[Click 'Generate new DOI']
    I --> J[Old DOI deprecated, new DOI issued]
    J --> K[Old DOI → `registered` state, new → `findable`]
```

### DOI States in DataCite

| State | Description |
|-------|-------------|
| `draft` | Being created, not yet public |
| `registered` | Registered but not findable (previous version) |
| `findable` | Public and discoverable (current version) |

When a new DOI is generated for a new revision:
- The **old** DOI transitions to `registered` (still valid, linked metadata)
- The **new** DOI is registered as `findable`
- Both DOIs point to the same repo (different revisions via `contentUrl`)

## Restrictions When DOI is Active

Once a DOI is generated for a repository:

- ❌ **Cannot delete the repository** — permanently locked
- ❌ **Cannot rename/move the repository** — `move_repo()` will fail
- ❌ **Cannot change visibility to private** — `update_repo_settings(private=True)` is blocked
- ✅ **Can still push commits** and update content
- ✅ **Can generate new DOIs** for new versions
- ✅ **Can add collaborators** with write access

To change these settings, file a support request at `website@huggingface.co`.

## Programmatic Patterns

### Pattern 1: DOI Discovery via DataCite Search

Search for all DOIs from a specific HF user/org:

```python
import requests

def list_hf_dois_for_creator(creator_name: str) -> list[dict]:
    """List all HF DOIs with a matching creator name."""
    params = {
        "query": f"10.57967/hf {creator_name}",
        "page[size]": 100,
        "sort": "-created"
    }
    resp = requests.get("https://api.datacite.org/dois", params=params)
    return resp.json().get("data", [])

# List all DOIs for a specific author
dois = list_hf_dois_for_creator("Thaweerath")
for item in dois:
    attrs = item["attributes"]
    print(f"{attrs['doi']} → {attrs['titles'][0]['title']} ({attrs['types']['resourceTypeGeneral']})")
```

### Pattern 2: Watch for New DOIs via DataCite API

DataCite API supports `created` and `updated` timestamps for polling:

```python
import requests, datetime

def get_recent_hf_dois(since: datetime.datetime) -> list[dict]:
    """Get all HF DOIs created since a given timestamp."""
    params = {
        "query": "10.57967/hf",
        "page[size]": 100,
        "sort": "-created",
        "created": f">{since.isoformat()}Z"
    }
    resp = requests.get("https://api.datacite.org/dois", params=params)
    return resp.json().get("data", [])
```

### Pattern 3: Generate Citation from DOI

```python
import requests

def get_citation(doi: str, fmt: str = "bibtex") -> str:
    """Get a citation string for a DOI in the specified format."""
    encoded = doi.replace("/", "%2F")
    url = f"https://api.datacite.org/dois/{encoded}"
    headers = {"Accept": f"application/x-{fmt}"}
    resp = requests.get(url, headers=headers)
    return resp.text

# Get BibTeX citation
bib = get_citation("10.57967/hf/8345", "bibtex")
print(bib)

# Get RIS citation
ris = get_citation("10.57967/hf/8345", "research-info-systems")
print(ris)
```

## HF API Integration Note

The Hugging Face Hub REST API (`/api/models/{id}`, `/api/datasets/{id}`) does
**NOT** expose a `doi` field in the response. The `huggingface_hub` Python
library has no `HfApi` methods for DOI generation or querying. DOIs are managed
entirely through:

1. **Hub UI** (Settings → DOI section) for generation/regeneration
2. **DataCite REST API** for programmatic querying
3. **Repo page header** for the DOI badge and citation button

## Relation to Storage Buckets

Since July 2026, HF Hub uses **Storage Buckets** for storage management
(https://huggingface.co/storage). Each repo has a storage bucket with size
limits. DOIs are a separate feature from storage — a DOI-locked repo cannot
be deleted but its storage bucket still counts against the user/org quota.
Generating a DOI does NOT increase storage limits.

## Zero-Cost Note

DOI generation on Hugging Face Hub is **free**. There is no charge for generating
a DOI. The DataCite API is also free to query (no authentication required for
read-only access). The only cost consideration is that DOI-locked repos are
permanent and their storage counts against your free tier bucket.
