# Session 2026-07-25 Evening — Lessons

## LoRA training on CPU
- 0.5B model can be fine-tuned via transformers on CPU (slow — ~40 min for 200 examples, 3 epochs)
- Must pass `labels` in tokenized dataset (same as `input_ids`) for causal LM loss
- PEFT LoRA with r=8, target_modules=["q_proj", "v_proj"] works on CPU
- Training monitor cron checks progress every 5 min
- **Update 2026-07-26**: Training OOM'd at step 14/150 (SIGKILL exit -9). Gradient checkpointing reduced speed to 25s/step but still not enough RAM. CPU training not viable for even 0.5B. Use Kaggle T4 for actual training.

## CI gitleaks on .curator_backups/
- HF Learn cron backups contain tar.gz archives that trigger gitleaks
- Fix: add `'''\.curator_backups/''',` to `.gitleaks.toml` allowlist paths

## CI empty commit trigger
- Commits with only deleted files (git rm --cached) may not trigger CI
- Use `git commit --allow-empty -m "ci: trigger"` or add whitespace change to README.md

## "If I said it not check, dont guess" — diagnosis first
Beer caught this twice this session. When checking CI status:
1. Always use the check-runs API (`/commits/<SHA>/check-runs`), not just commit status
2. If state is "pending", check the actual list of in-progress vs completed checks
3. Never say "probably just a delay" — read the data
4. If you can't read the CI log (403), say so and try another method — don't fill in gaps with guesses
