# Session 2026-07-25 — Lessons

## Layout preference: narrow tables or bullet lists
Beer said "Better layout 😤" when presented with wide multi-column tables. Max 3 columns for tables. For 5+ dimensions, split into multiple small tables or use bullet groups. Task lists (`- [ ]`) for yes/no states. When in doubt, bullet lists beat wide tables.

## Cardinal rule: diagnose before fixing
"If I said it not check, dont guess" — when checking a status (CI, model count, any state), actually query the source, read the raw results, and report ONLY what the raw output confirms. Do not fill gaps with assumptions.

## Ask before removing persona references
Removing saktan from config/tests without asking first was wrong. Even with no running agent, Beer may want the reference kept. Ask before modifying ANY persona reference.

## CI Health Check cron limitation
The CI Health Check cron can report "ok" while CI is actually failing, because it checks its OWN execution status, not the CI workflow results. Always verify real CI status by querying the check-runs API directly, not just the cron's status.
