# 2026-07-30: context-0.5b Cron Eval — model-index & cron-mode pitfalls

## Scenario
Cron-driven health eval for `Nanthasit/sakthai-context-0.5b-merged`. No user present. Zero-cost, single-model check.

## Key Findings

### 1. `cardData.model-index` vs top-level `model-index`
The raw API response has TWO model-index locations:
- **Top-level**: `response["model-index"]` — contains the real published values (e.g. `Selection Accuracy: 91.2`)
- **`cardData["model-index"]`** — may contain stale/wrong data (different model name, `"pending"` values)

**Root cause:** `?expand[]=cardData` returns card YAML metadata which may lag behind the published model-index on the card.

**Fix:** Always fetch the raw API separately and read from the top-level `model-index` field:
```python
raw = requests.get(f'https://huggingface.co/api/models/{model_id}', headers=auth).json()
benchmarks = raw.get('model-index', [])  # not raw.get('cardData', {}).get('model-index', [])
```

### 2. Cron-mode tool restrictions
Three tools blocked in cron mode:
- **`execute_code`** (Python with hermes_tools) — blocked outright; cannot use `from hermes_tools import terminal`
- **`curl | python3` pipe** — blocked by security scanner (HIGH risk)
- **`write_file` to `/tmp`** — `/tmp` is a protected path in cron mode

**Workflow that works:** `curl -o /tmp/file.json` → `read_file` → `python3 -c` on saved files → `write_file` to cwd (not `/tmp`)

### 3. `list_models()` direction parameter
`HfApi.list_models(sort='downloads', direction=-1)` raises `TypeError: unexpected keyword argument 'direction'` in huggingface_hub v1.25. Remove `direction` — sort defaults to descending.

### 4. Model file sizes via `list_repo_tree`
`model_info().siblings` has `size: None` for weight files. Use `list_repo_tree()` instead:
```python
tree = {i.path: i for i in api.list_repo_tree(repo_id)}
size = tree.get('model.safetensors').size  # works
```
This works for both safetensors and GGUF files.
