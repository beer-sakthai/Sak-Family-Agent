## Lessons

1. **Every cron-run health check adds a new YAML to `.eval_results/`.** Without pre-cleanup, the directory fills with orphaned files within a single day.
2. **The sibling `rfilename`-only shape (no size, no lfs) is another Xet/CAS metadata sparsity variant** on top of the documented `size: null, lfs: null` pattern.
3. **`delete_file` collisions** between sibling cron jobs produce 404s. Catch silently: if the file is already gone, that's the desired state.
4. **The verify script didn't detect the `generic` schema** used by this cron's health-check YAML (top-level keys: `model`, `timestamp`, `metadata`, `age`, `popularity`, `repo_content`, `assessment`). The script was patched to add `generic` schema support.
