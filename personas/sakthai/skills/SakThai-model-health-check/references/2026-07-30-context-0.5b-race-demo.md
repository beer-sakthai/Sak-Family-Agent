# 2026-07-30: sakthai-context-0.5b-merged Sibling Race Demo

## Context

Cron evaluation of `Nanthasit/sakthai-context-0.5b-merged`. Three companion cron jobs
(embedding, TTS, plus-1.5b) ran simultaneously on the same host, all writing to
`.eval_results/health-check.yaml` — the canonical local path.

## Timeline of Collisions

| Time | Event |
|------|-------|
| 21:14:00 | Wrote 0.5B health-check to `.eval_results/health-check.yaml` (1681 bytes) |
| 21:14:01 | Sibling subagent `79290acd` **overwrote** it with embedding model report |
| 21:15:58 | Re-read file — found embedding data, 98 lines, not our model |
| 21:16:00 | Re-wrote 0.5B data |
| 21:16:01 | Sibling `c0964d26` **overwrote** it again with plus-1.5b-coder report |
| 21:16:03 | Re-read — found plus-1.5b-coder data |
| 21:16:05 | Wrote model-specific unique filename `health-check-0.5b-merged.yaml` — no further collisions |

## Detection Signals

1. **YAML content mismatch** — expected `sakthai-context-0.5b-merged` but found
   `sakthai-embedding-multilingual` or `sakthai-plus-1.5b-coder` after reading back.
2. **Hermes `_warning` field** — `write_file` returned a warning like:
   `"was modified by sibling subagent 'c0964d26-f7d7-4642-9113-d9214f332679' at 21:16:03
   — after this agent's last read at 21:15:58. Re-read the file before writing."`
   This fires when a sibling agent wrote between your last `read_file` and your `write_file`.
3. **Ad-hoc verification failure** — regex checks for `downloads: 1370` failed because
   the file no longer contained 0.5B data.

## Resolution

1. Switched to model-specific local filename: `.eval_results/health-check-0.5b-merged.yaml`
2. Uploaded to HF under two paths:
   - `health-check-0.5b-merged.yaml` (unique, no collision)
   - `health-check-2026-07-30.yaml` (timestamped, no collision)
3. Uploaded stable `health-check.yaml` to HF but expected it might be overwritten —
   treated it as convenience, not canonical

## Key Takeaway

The stable local path `.eval_results/health-check.yaml` is UNSAFE when multiple
cron subagents run concurrently. Use a model-specific filename locally and
upload to a model-specific dated path on HF as the canonical record.
