# ?blobs=true Metadata Nullification on LoRA Adapters

**Date:** 2026-07-30
**Model:** `Nanthasit/sakthai-plus-1.5b-lora`
**Type:** LoRA adapter (PEFT) — no `safetensors` top-level key, but `adapter_model.safetensors` present (70.49 MB), `usedStorage` = 750 MB.

## Discovery

Calling the HF API with `?blobs=true&expand[]=siblings` query params returned `null` for top-level scalar fields that have real values when fetched without query params:

### With `?blobs=true&expand[]=siblings`

```python
downloads = None     # should be 0
likes = None         # should be 0
lastModified = None  # should be "2026-07-30T21:48:25.000Z"
createdAt = None     # should be "2026-07-30T13:02:41.000Z"
pipeline_tag = None  # should be "text-generation"
library_name = None  # should be "transformers"
usedStorage = None   # should be 750538597
siblings = [...]     # 13 entries with real sizes (3043, 5364, etc.)
_id = "6a6b4b715a63a3ab9e95b02a"  # present
```

### Without any query params (base URL)

```python
downloads = 0
likes = 0
lastModified = "2026-07-30T21:48:25.000Z"
createdAt = "2026-07-30T13:02:41.000Z"
pipeline_tag = "text-generation"
library_name = "transformers"
usedStorage = 750538597
```

## Root Cause

The HF API's blob-cache layer partially short-circuits for repos that lack a top-level `safetensors` key. LoRA adapters have `adapter_model.safetensors` (via siblings) but no `safetensors` key in the top-level JSON. The blob-cache measures the LFS blobs (populating sibling `lfs` sub-dicts) but skips populating scalar metadata fields.

This differs from the skeleton-repo collapse (where the entire response shrinks to ~800 bytes with only `_id`, `id`, `siblings`) — here the sibling data and `_id` were fully present, only the scalar metadata fields were nullified.

## Impact

If a health-check script blindly uses `?blobs=true` to get file sizes in one call, it gets null metadata and produces an incorrect report (downloads=null, likes=null, etc.) or crashes when computing velocity.

## Fix

Skip `?blobs=true` entirely for LoRA adapters. Use:
1. Base API URL (no params) for metadata
2. Tree endpoint for file sizes

This pattern works for all model types (no branching needed) and avoids the field nullification entirely.
