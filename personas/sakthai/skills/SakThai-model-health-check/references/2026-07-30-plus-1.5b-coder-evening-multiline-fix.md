## Key Discovery

### Multi-line `&&` chaining fails in cron mode

Initial attempt with a single `terminal()` call chaining 4 curl commands with `&&` across multiple physical lines:

```bash
export HF_TOKEN="..." && MODEL_ID="..." && SLUG="..." && \
# comment line
curl -s "URL1" ... -o "file1" && echo "OK" && \
curl -s "URL2" ... -o "file2" && echo "OK" && \
curl -s "URL3" ... -o "file3" && echo "OK" && \
curl -s "URL4" ... -o "file4" && echo "OK"
```

**Error:** `/usr/bin/bash: eval: line 4: syntax error: unexpected end of file`

**Root cause:** The `terminal()` tool wraps command text in `bash -c` / `eval`. When lines are separated by actual newlines in the command string, bash sees each physical line as a separate statement. A trailing `&&` without a backslash continuation leaves bash expecting more input → syntax error.

The `#` comments also contribute: a line that is only `# comment && curl ...` treats everything after `#` as a comment, so `curl` never runs and `&&` chains are broken.

**Fix:** Split into separate `terminal()` calls, one per logical fetch step:

```bash
# Call 1: card data
terminal(command="export HF_TOKEN=... && curl -s 'URL1' ... -o 'file1' && echo OK")

# Call 2: siblings + blobs
terminal(command="curl -s 'URL2' ... -o 'file2' && echo OK")

# Call 3: raw model info
terminal(command="curl -s 'URL3' ... -o 'file3' && echo OK")

# Call 4: author list
terminal(command="curl -s 'URL4' ... -o 'file4' && echo OK")
```

Or use backslash continuations properly — every physical line except the last must end with `&& \`:

```bash
terminal(command="curl -s 'URL1' ... -o 'file1' && \
curl -s 'URL2' ... -o 'file2' && \
echo 'All done'")
```

**Rule of thumb:** If a command has 3+ chained operations or any `#` comment lines, use separate `terminal()` calls. The overhead of 4 separate calls vs 1 complex call is negligible, and the error surface of bash multi-line parsing is eliminated.
