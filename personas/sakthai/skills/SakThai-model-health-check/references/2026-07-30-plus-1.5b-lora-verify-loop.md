## Summary

Routine health check. Sibling subagent overwrote `.eval_results/health-check.yaml` with `sakthai-plus-1.5b-coder` data between write and upload, and again after the re-write but before the system's ad-hoc verification completed. Documenting the verification loop so agents recognizing this pattern can short-circuit the recovery.

## Verification Loop Pattern

When a sibling collision occurs mid-session, the ad-hoc verification system enters a loop:

```
Turn 1: write_file → (sibling overwrites in background) → system emits "unverified" warning
Turn 2: verify checks → detects WRONG model → re-writes correct content → re-uploads
Turn 3: system emits "unverified" again (file changed) → verify checks → PASS
```

Key observations:
- The verification system checks the **current file content**, not the intent. Even if you already verified the file was correct, a subsequent sibling overwrite resets the verification state.
- The fastest recovery is: detect (via content check), re-write, re-verify in one cycle.
- The loop terminates when the file stabilizes (no sibling agent overwriting in the 15–30s window between write and verification).

## Cheat: Fast-track recovery in one turn

```python
# After detecting wrong content via checks:
import os
from huggingface_hub import HfApi

# 1. Restore from HF if the correct version was already uploaded
api = HfApi()
local = api.hf_hub_download(
    REPO_ID, ".eval_results/health-check.yaml", repo_type="model"
)
with open(local) as f:
    content = f.read()
if REPO_ID in content:
    # Remote is correct — just restore locally and re-verify
    with open("/opt/data/.eval_results/health-check.yaml", "w") as f:
        f.write(content)
    # Re-upload on stable path (sibling may have clobbered it on HF too)
    api.upload_file(
        path_or_fileobj="/opt/data/.eval_results/health-check.yaml",
        path_in_repo=".eval_results/health-check.yaml",
        repo_id=REPO_ID, repo_type="model",
        commit_message=f"re-upload after sibling collision [automated]"
    )
    # Now the file is correct locally and on HF
```

This avoids re-fetching from the HF API (saves 1–2 curl calls) when the remote is the correct version.
