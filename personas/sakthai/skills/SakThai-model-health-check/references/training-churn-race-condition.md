# Active-Training Race Condition (HF repo card churn)

**Symptom:** You apply a card fix (README, pipeline_tag, license) to a HF
repo, verify it live via API — and a follow-up check 20 min later shows the
fix is GONE, with the card back to the autogenerated template.

**Real example (2026-07-31, Nanthasit/sakthai-plus-1.5b-lora):**
- 01:29Z fix pushed (`pipeline_tag: text-generation`, `license: apache-2.0`,
  enriched 3,832-byte README) → verified live, 14/14 checks pass.
- 01:34Z `Upload README.md with huggingface_hub` commit reverted it.
- Commit history showed why: TRL checkpoint pushes
  `Training in progress, step 100` (01:26Z), `step 200` (01:39Z),
  `step 300` (01:53Z) — every ~13 min. Training was LIVE.

## Rule

**Before applying any card/README fix, check for active training first.**
If the repo is being re-trained, do NOT fight the churn loop — any edit is
clobbered within one push cycle (~13 min per 100 steps). Instead:

1. Document the issue as `status: reverted` in the health report (not `fixed`).
2. Record the root cause + remediation in the report.
3. Add a `recheck_hook` to the tracker: "If last_commit_age > 30 min and no
   'Training in progress' in recent titles, re-apply the fix."
4. Keep the enriched card content saved locally so it can be re-applied
   post-training without re-authoring.

## Diagnostics

```python
from huggingface_hub import HfApi
from datetime import datetime, timezone
api = HfApi()
commits = api.list_repo_commits("AUTHOR/repo", repo_type="model")
latest = commits[0]
age = (datetime.now(timezone.utc) - latest.created_at).total_seconds()
print(latest.title, f"{age:.0f}s ago")
# "Training in progress, step 300" + age < 1800s  => training is LIVE
```

- Commit titles containing `Training in progress` = TRL `push_to_hub`
  checkpoint strategy — the autogenerated README rides along.
- Cadence: step N → N+100 ≈ 13 min → extrapolate how long churn lasts.
- Check `AUTHOR/kaggle-notebooks` dataset + local crons for the training
  script before assuming you can patch the root cause. If the orchestrator
  is external (Kaggle session not exported), you can't — recheck-hook it.

## Double-verification pattern (what caught the revert)

Verify remote state AFTER upload — more than once if time passes:
- Pass 1 right after upload (fix confirmed live).
- Pass 2 on the final report (catches reverts/regressions).
A local-only verify misses this class of failure entirely.

## LoRA autogenerated TRL card pitfalls

The TRL `push_to_hub` README template ships with three recurring defects —
check every LoRA/`generated_from_trainer` card:
- `pipeline_tag` missing → `None` → model invisible in pipeline search.
  Fix: `pipeline_tag: text-generation` in YAML frontmatter.
- `licence: license` typo (invalid SPDX identifier) → card metadata
  `license: None`. Fix: `license: apache-2.0`.
- Minimal template README (no dataset links, no usage example, no
  cross-links to the merged model). Fix: add `datasets:`, usage snippet,
  link to merged sibling + family collection.
