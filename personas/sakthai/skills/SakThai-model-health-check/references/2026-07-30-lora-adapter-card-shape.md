# LoRA Adapter Card Shape

Observed on `Nanthasit/sakthai-plus-1.5b-lora` (2026-07-30).

## cardData shape

LoRA adapters (PEFT repos) have a **simpler** cardData than full-model repos:

```json
{
  "base_model": "Qwen/Qwen2.5-1.5B-Instruct",   // string, not object
  "library_name": "transformers",
  "model_name": "sakthai-plus-1.5b-lora",
  "pipeline_tag": "text-generation",
  "tags": ["generated_from_trainer", "trl", "sft", "qwen", "lora", "peft", "instruct"],
  "license": "apache-2.0"
}
```

Key differences vs full-model repos:

| Field | Full model | LoRA adapter |
|-------|-----------|--------------|
| `base_model` | String (or absent) | String — always present, points to base |
| `base_model_info` | Dict (type, modelId, config) | **Absent** — not generated by TRL/PEFT |
| `tags` | ~5-10 | ~7-8 including `lora`, `peft`, the base model family |
| `library_name` | `transformers` | `transformers` |
| `datasets` | Often present | Typically `[]` |
| `language` | Often present | Typically `[]` |

## File shape

LoRA repos have 15 siblings (adapter + full tokenizer):

| Role | File | Size |
|------|------|------|
| Weights | `adapter_model.safetensors` | ~70.5 MB (r=16, 7 modules) |
| Adapter config | `adapter_config.json` | ~1 KB |
| Tokenizer | `tokenizer.json` | ~10.9 MB (full Qwen tokenizer) |
| Tokenizer config | `tokenizer_config.json` | ~700 B |
| Chat template | `chat_template.jinja` | ~2.5 KB |
| Training args | `training_args.bin` | ~5.6 KB |
| README | `README.md` | ~6.6 KB |
| .gitattributes | `.gitattributes` | ~1.6 KB |
| .eval_results/ | (7+ previous health checks) | ~4 KB each |

## Storage discrepancy

`usedStorage` (715.77 MB) is ~9× the sum of file sizes (~81 MB). This is normal for LoRA adapters pushed via `huggingface_hub` with full tokenizer data — the git history and Xet backend overhead inflate the storage number. The ratio is consistently ~9-10×, much higher than full-model repos (~1.3-2×).

## Implications for health scoring

When scoring a LoRA adapter's card quality:
- **DO NOT penalize** missing `base_model_info` — it's structurally absent from PEFT-created repos
- **DO NOT penalize** empty `datasets`/`language` arrays — standard for adapter-only repos
- **DO NOT penalize** `usedStorage : file_sum` ratio over 1.3× — LoRA adapters inherently have poor ratios due to small weight-to-tokenizer proportion
- **DO verify** `base_model` is present as a string — this is the critical field for merging
