# All-Zero Siblings on Brand-New Model

**Date:** 2026-07-30
**Model:** Nanthasit/sakthai-plus-1.5b (created ~9.8 hours prior)
**Pattern:** API siblings ALL returned `size=0` — including non-weight files

## Symptoms

```python
# From /api/models/Nanthasit/sakthai-plus-1.5b (no ?blobs=true, no ?expand[])
siblings = data.get('siblings', [])
for s in siblings:
    print(s.get('rfilename'), s.get('size'), bool(s.get('lfs')))
# model.safetensors         0  False    ← not LFS flagged
# config.json               0  False
# README.md                 0  False
# tokenizer.json            0  False
# .gitattributes            0  False
# ... 13 files total, ALL size=0
```

But the actual files exist and are non-zero:
```
model.safetensors     → 3,087,467,144 bytes (via HEAD /resolve/main/ → follow redirect → Content-Length)
config.json           → 1,373 bytes
tokenizer.json        → 11,421,892 bytes
```

## Root Cause

Blob indexing / API cache had not caught up with the upload (~4 minutes old at scan time). The model was created at `2026-07-30T13:02:40Z` and last modified at `2026-07-30T22:48:48Z` — only ~4 minutes between upload completion and the health-check scan. The REST API siblings endpoint returns pending/zero sizes during the window between file upload and full blob metadata propagation.

## How It's Different From Previously-Documented Patterns

| Pattern | Shape | Files affected | LFS key present? |
|---------|-------|---------------|------------------|
| **Xet/CAS** | `{'rfilename': ..., 'size': null, 'lfs': null}` | Weight files only | Yes (null) |
| **LoRA adapter** | `{'rfilename': ...}` (size key absent) | All siblings | No |
| **Fresh model (this)** | `{'rfilename': ..., 'size': 0, lfs absent}` | ALL siblings | No |

Key distinction: **every file** returns `size=0`, not just weight-bearing files. README.md, config.json, .gitattributes — all 0. This is the fingerprint of an indexing backlog, not a storage backend quirk.

## Detection

```python
# After fetching siblings:
all_zero = all(s.get('size', 0) == 0 for s in siblings)
any_lfs = any(s.get('lfs') is not None for s in siblings)
weight_files = [s for s in siblings if any(w in s.get('rfilename','')
                for w in ['.safetensors','.gguf','.bin','.pth'])]

if all_zero and not any_lfs and weight_files:
    # Suspect fresh-model index backlog
    # Verify by checking actual file existence via HEAD /resolve/main/
    import urllib.request
    from huggingface_hub import hf_hub_url, get_hf_file_metadata
    meta = get_hf_file_metadata(hf_hub_url(repo_id, weight_files[0]['rfilename']))
    if meta.size > 0:
        print(f'Index backlog confirmed: API says 0, actual is {meta.size}')
```

## Resolution

Prefer `files_metadata=True` which re-fetches with accurate blob metadata:

```python
from huggingface_hub import HfApi
api = HfApi()
info = api.model_info(repo_id, files_metadata=True)
```

If still zero, fall back to HEAD redirect or `get_hf_file_metadata` (see skill Methods A/B).

## When to Suspect This vs. Skeleton

If ALL files show `size=0`, AND weight-bearing files exist in the sibling list, AND the model was created within the last few hours — verify via HEAD before concluding skeleton. A skeleton consistently returns 404 or error body; a backlogged repo returns real Content-Length on redirect.
