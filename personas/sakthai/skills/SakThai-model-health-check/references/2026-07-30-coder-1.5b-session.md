# Coder 1.5B Health Check — 2026-07-30 Session

## Data Structure Findings

### Model-index uses `results` not `tasks`

The HF API model-index at the top level of `/api/models/{id}`:

```json
{
  "model-index": [
    {
      "name": "sakthai-coder-1.5b",
      "results": [
        {
          "task": {"type": "text-generation"},
          "dataset": {"name": "HumanEval", "type": "openai_humaneval"},
          "metrics": [
            {"name": "pass@1 (base model reference)", "type": "pass@1", "value": 74.4, "verified": false}
          ]
        }
      ]
    }
  ]
}
```

- Top-level key is `model-index` (hyphenated).
- Each entry has `results` (list), NOT `tasks`.
- Each result has `task` (sub-object), `dataset`, `metrics` at the same level.
- `verified` is a boolean on each metric; `false` means unconfirmed.

### `?expand[]=cardData` nesting

Response nests card metadata under `cardData` key:

```json
{"_id": "...", "id": "...", "cardData": {"license": "...", "tags": [...], ...}}
```

Access as `response['cardData']`, not top-level.

### GGUF file sizes via API

`/api/models/{id}` top-level `gguf` key provides:
- `gguf.totalFileSize`: exact file bytes on disk (e.g. 1117320768)
- `gguf.total`: uncompressed tensor size

When sibling API returns `size: 0` for Xet-backed GGUF files, use this GGUF key for accurate storage totals.
