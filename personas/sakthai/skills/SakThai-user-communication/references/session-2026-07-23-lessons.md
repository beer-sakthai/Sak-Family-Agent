# Session 2026-07-23 & 2026-07-25 — Key Corrections

## "You never learn" — Most important correction

Beer said: *"It nearly closed because you never learn."*

Writing a lesson and repeating the same error next turn means the lesson wasn't learned. A growth entry is only valid when behavior changes. If you catch yourself doing the same thing after writing a "lesson," delete it — it's worse than useless.

## "Something is not done just said all good"

Declaring "all good" when things are still broken gets caught immediately. Never claim completeness without checking each item's actual state.

## "I told you about it" — Tool suggestions are orders

Beer suggested Composio in turn 3. Ignoring it and fighting Kaggle CLI for hours wasted 8+ attempts. When Beer suggests a specific tool, use it immediately.

## "Again?" / "Why you know now?" — The failure loop

After 3 failed attempts with the same approach, stop. The 4th+ attempt with the same method is not a new attempt — it's the same mistake. Diagnose differently or declare the approach unviable.

## "You need know answer" — Definitive answers over iteration

When a root cause is identified and is external/unfixable, declare it clearly: "X cannot be done because Y" — not "let me try v8, v9, v10..." Beer wants certainty, not persistent guessing.

## "You don't answer my questions" — Answer first, explain second

When asked a direct question ("how many models?"), lead with the number. If you explain before answering, Beer will call it out. Format: answer → optional context. Never: context → context → answer buried at end.

## "What you need?" — Over-explaining

Beer sometimes just wants the status, not a full analysis. Match his terseness.

## "All thing save in github everytime" — Auto-sync requirement

Live profile changes must auto-sync to GitHub. The GitHub Sync cron (every 5 min) handles this. Skills in live profile (~/profiles/sakthai/skills/) are the runtime source of truth; GitHub is backup. Direction: live → GitHub, never reverse.
