# Hugging Face MCP Server

## What It Is

The **Hugging Face MCP (Model Context Protocol) Server** connects any
MCP‑compatible AI assistant directly to the Hugging Face Hub. Once connected,
your assistant can search and explore Hub resources, use community tools, run
Jobs, and more — all from within your editor, chat, or CLI.

Supported clients: Claude Desktop, VS Code extensions, Cursor, Codex, Zed,
ChatGPT, and any MCP‑compatible agent.

## Quick Start

1. Go to **https://huggingface.co/settings/mcp** while logged into your HF
   account.
2. Select your MCP client from the list (Cursor, VS Code, Zed, Claude Desktop,
   etc.). The page generates your exact configuration snippet.
3. Paste the snippet into your client's MCP configuration file, save, and
   restart/reload the client.
4. You should see "Hugging Face" listed as a connected MCP server.

**Important:** The settings page generates the exact config your client expects.
Use it rather than writing config by hand.

## Built-in Tools

| Tool | Description |
|------|-------------|
| `hf_fs` | Core hub navigation tool — search models, datasets, Spaces, papers, docs |
| Contribute Repos | Create repositories and write files to them |
| Sandboxes | Create and use sandboxes including file management |
| Run & Manage Jobs | Run, monitor, and schedule Jobs on HF infrastructure |

The `hf_fs` tool handles most Hub tasks. It enables semantic search of
documents and Spaces directly from your assistant.

## Adding Community Tools (Spaces)

You can extend your setup with **MCP-compatible Gradio Spaces** built by the
community:

1. Browse Spaces with MCP support at: https://huggingface.co/spaces?mcp=true
2. Add the relevant Space in your MCP settings at
   https://huggingface.co/settings/mcp
3. Gradio MCP apps expose their functions as tools (with arguments and
   descriptions) so your assistant can call them directly.
4. Restart/refresh your client so it picks up new tools.

### Spaces Options

| Option | Description |
|--------|-------------|
| **Dynamic Spaces** | Dynamically call MCP Spaces at runtime. Your assistant discovers and uses MCP-compatible Spaces on-the-fly without manual addition. |
| **Remove Embedded Images** | Remove embedded images generated by Gradio Spaces. Useful if your MCP client has limited image support. |

## Building an MCP Server with Gradio

Any Gradio app can become an MCP server with a single flag:

### Minimal example

```python
import gradio as gr

def letter_counter(word: str, letter: str) -> int:
    """Count how many times a letter appears in text."""
    return word.lower().count(letter.lower())

demo = gr.Interface(
    fn=letter_counter,
    inputs=[gr.Textbox("strawberry"), gr.Textbox("r")],
    outputs=[gr.Number()],
    title="Letter Counter",
    api_name="predict"
)

if __name__ == "__main__":
    demo.launch(mcp_server=True)
```

**Key points:**
- Include a detailed **docstring** on your function — it becomes the tool
  description for the LLM
- Set `mcp_server=True` in `.launch()`
- The function name becomes the tool name
- Initial values in input components become default parameter values
- Accessible at `http://your-server:port/gradio_api/mcp/`

### Environment variable alternative

```bash
export GRADIO_MCP_SERVER=True
```

### Viewing schemas

Visit `http://your-server:port/gradio_api/mcp/schema` or click "View API" in the
Gradio app footer, then the "MCP" tab.

### Performance tuning

Set `queue=False` in event handlers to minimize latency (up to 10× throughput).
Disables progress notifications — only recommended for short-running tasks.

## Authentication Patterns

### Private Spaces

Use a private Space as an MCP server by providing your Hugging Face token in the
client config:

```json
{
  "mcpServers": {
    "my-private-space": {
      "url": "https://username-my-private-space.hf.space/gradio_api/mcp/",
      "headers": {
        "Authorization": "Bearer YOUR_HF_TOKEN"
      }
    }
  }
}
```

### Accessing request headers (gr.Request)

```python
import gradio as gr

def echo_headers(x: str, request: gr.Request):
    return str(dict(request.headers))

gr.Interface(echo_headers, "textbox", "textbox").launch(mcp_server=True)
```

### Token extraction (gr.Header)

```python
import gradio as gr

def make_api_request(
    prompt: str,
    x_api_token: gr.Header
):
    """Make a request authenticated with the caller's token."""
    return "Hello!" if not x_api_token else "Hello with token!"

demo = gr.Interface(
    make_api_request,
    [gr.Textbox(label="Prompt")],
    gr.Textbox(label="Response"),
)
demo.launch(mcp_server=True)
```

The `gr.Header` type automatically extracts the named header from the incoming
MCP request. The MCP connection UI will also display which headers the server
expects.

## Converting an Existing Space

1. **Duplicate** the Space if it's not yours (enables edits).
2. **Add docstrings** to functions you want exposed as tools.
3. **Add** `mcp_server=True` in `.launch()`.
4. Redeploy to Spaces — it's now an MCP server.

## STDIO Transport

Gradio automatically generates an additional **stdio-based MCP server** for file
uploads. This can upload files to any remote Gradio app and returns a URL usable
for subsequent tool calls — useful when your client doesn't support URL-based
file references.

### Proxy Tools via CSV (`PROXY_TOOLS_CSV`)

Load external MCP endpoints as tools at server startup:

```
tool_name,url,response_type
papers,https://evalstate-hf-papers.hf.space/mcp,SSE
```

- Single upstream tool → tool name = CSV `tool_name`
- Multiple upstream tools → tool names = upstream tool names
- Collisions → proxy tool skipped (warning logged)
- Bouquet `proxy` enables all CSV-loaded tools
